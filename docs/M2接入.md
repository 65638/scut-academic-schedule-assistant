## 入口与数据

`platform/scut-schedule/skills/scut-schedule/scripts/notice_runtime.py` 提供 `notice`、`correction`、`snapshot`。三个入口仅计算，不联网、不缓存账号或表格 ID。输出的 `records`、`updates` 可交给 A 现有原生 library 流程，`saved_to_cloud=false` 不表示保存成功。

通知输入沿用 C 的 `source/profile/today/candidate_extraction`。`save_requested` 默认 false，只有用户明确要求保存或更新时才传 true。`applicability_confirmed` 默认 false，仅表示用户已确认本次通知的未知适用条件；它不能覆盖明确不适用的判断。条件改变或更换通知后重新核对。

更正输入包含 `original_source/correction/target_event_id` 和 `mode/profile/today`，`correction.corrects` 标明版本关系。原文重传保留既有事项的用户修改；同一编号的不同正文要求更正，不静默覆盖。更正按唯一目标与当前前值检查，只写变化字段；来源和前后值加入原来源 JSON 的历史。材料与适用对象存于 M2 元数据，继续使用原个人表字段。

## 复现命令

在仓库根目录使用 Python 3.9+，仅标准库：

```sh
python -m unittest discover -s tests -v
python -m unittest discover -s modules/m2/tests -v
python platform/scut-schedule/skills/scut-schedule/scripts/notice_runtime.py notice --input platform/scut-schedule/skills/scut-schedule/examples/m2-notice-save.json --out work/m2-plan.json
```

首条示例生成 `handoff-c-event-001`，日期 `2026-11-25`，截止 `17:00`。在实际写入并读取个人表后，将新 CSV 交给以下命令：

```sh
python platform/scut-schedule/skills/scut-schedule/scripts/notice_runtime.py correction --existing work/latest.csv --input platform/scut-schedule/skills/scut-schedule/examples/m2-notice-correction.json --out work/m2-update.json
python platform/scut-schedule/skills/scut-schedule/scripts/notice_runtime.py snapshot --existing work/latest.csv --mode example --today 2026-11-23 --out work/m2-current.json
```

更正计划将同一事项日期改为 `2026-11-27`，时刻仍为 `17:00`。第二条 snapshot 需要传入实际应用更正后重新读取的快照，不能用更正前 CSV 冒充已更新结果。以 11 月 23 日为示例查看日可在同一周看到更正前后事项；这不改变共同样例 11 月 16 日的原日期。

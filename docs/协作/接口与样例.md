# 对接字段与样例

本页对齐 A 已交的 M0 数据格式（`a/platform-v0`，`5c55bb1`）。当前目的为让 B、C、D 开始独立开发，不增加通用接口框架。函数名可由成员选择，交付时说明调用方式，A 负责组合和适配。

## 最小交换结构

外层 `bundle` 包含 `mode`（`example` 或 `real`）、`today`、`timezone`（`Asia/Shanghai`）、`campus`（`大学城校区`）、`sources` 和 `events`。以 `联调样例.json` 中 `B.expected_bundle` 为完整例子。

| 事项字段 | 含义 |
| --- | --- |
| id、type、title | 稳定编号、类型和标题；现用 activity，首批约定另用 course、submission、notice_task |
| date、start_time、end_time | YYYY-MM-DD、HH:MM；未知为 null；提交事项用 start_time 表达截止时刻，end_time 留空，显示时按 type 写“截止” |
| end_date（可选） | 明确的跨日结束日期；不提供时只按同日区间处理。0.5.0 适配器存于每行 source.event_end_date，恢复为事项字段，个人表仍为 15 列 |
| location、status | 地点；M0 当前支持 not_started、in_progress、completed、cancelled |
| pending_fields | 待确认字段数组；M0 尚不支持 pending 状态值，暂用 not_started 配合该数组 |
| source_id、source_excerpt | 指向来源编号，保留本事项的原文片段 |

来源用 `id`、`type`、`title`、`mode`、`text`；消息加 `sent_on`，通知加 `publisher`、`published_on`、`url` 或 `file_name`。导入时 A 补 `ingested_at`。公开资料原文里没有的字段保持未知。

画像是可选的独立输入，包含 campus、college、major、grade、education_level。没有学院或专业条件的通知不因此追问；存在影响相关性判断的限制而用户画像缺失时才问。首版专业不限不等于通知没有适用限制。

## 谁给谁什么

| 交接 | 输入 → 输出 | 持久化 |
| --- | --- | --- |
| C → B／A | 通知正文和来源 → 行动、适用条件、日期表达、材料、入口、依据 | C 不写用户表 |
| B → A | 带来源的消息／候选项和发送日 → bundle、待确认信息 | A 写表 |
| B → A（更新） | 当前事项、明确变更和新来源 → 目标事项编号、变更字段或待选择候选 | A 原位更新；重复输入不等于合法修改 |
| A → D | 已保存事项、模式、今天、实际变化 → 周计划／简报、待确认、冲突建议 | D 不写用户表 |

地点更正返回 `target_event_id`、`changes` 和完整 `source`（含原文、发送日、标题和模式）。A 的 `runtime.py location` 将更正转为原位补丁，历史保存于原来源列的 `event_history`，包含前后变化和完整更正来源；原 source_id/source_excerpt 保留。M0 的 prepare_import 仅用于新增，不作为更新函数。

M0 本地 CSV 为存储适配层，来源放在 `source` JSON 列，pending_fields 序列化为 JSON 文本。B/C/D 交换正常 JSON，不需要各自处理 WorkBuddy 表格字段包装。A 当前按编号去重，并不等于任意同义重述均可去重；B 要明确事项关联依据。

在线个人表是持久数据源，本地 CSV 只是临时快照。A 的 `runtime.py snapshot --existing latest.csv --mode example --today 2026-11-16 --out current_bundle.json` 已完成交接转换：还原 null 和 pending_fields 数组，按来源编号整理 sources/events，同时输出事项 history 和顶层 questions。D 使用该 bundle；M0 week() 的原始 CSV 行不是 D.input_bundle。

0.5.0 的 `presentation_runtime.py` 直接接最新 CSV，调用 notice_snapshot 后输出 week／tonight／week-brief／conflicts／free／prepare。跨日课程仅移动日期时保留原跨度并记录 end_date 前后变化；已有单日课程的时间检查保留。完成、取消事项仍在快照中，M3 从提醒与占用中排除。

## 共同口径

- 示例今天 2026-11-16，示例学期自 2026-08-31 起。周为周一到周日；三天内为今天、明天、后天。
- 相对日期基于消息原发送日，不能用示例今天替代缺失的发送日。只有日期不补 23:59。
- 日期未知仍保留事项和 pending_fields。D 应展示所有含待确认字段的事项；M0 当前 week 只把无日期项放 pending，接入时须补齐这一差异。
- 重放相同来源不得覆盖用户后续修改。缺结束时刻不推算活动时长；不将 submission 截止时刻当作占用时段去判冲突。
- 联调样例中的人、通知、课程和教室均为合成示例，不能作为华工真实校历、作息或通知。

## 第一轮接通后检查什么

B 组的消息得到两个事项，修改班会不动交表；C 组通知有来源且截止正确；D 组周计划能显示这些记录并列出缺日期事项。A 接入后再测同一结果能否保存和恢复，D 验证第二账号。每人把自己实际输出随交接单附上即可，不另设用例数量或覆盖率指标。
